3. Каждый промпт написан так, чтобы его можно было скопировать и вставить как есть.
4. "Без полумер" = ни один шаг не должен закрываться заглушкой/моком, если явно не указано обратное. Обработка ошибок, валидация вводимых данных и понятные сообщения — обязательны на каждом шаге, а не "потом добавим".

## 1. Описание проекта

Сервис QR-меню для мини-заведений (кофейни, стритфуд, мини-кафе, бары). Заведение размещает QR-код на столе → клиент сканирует → открывается веб-страница меню. Без установки приложений и без регистрации для клиента.

Мультитенантность: один код, одна БД, разделение данных по `venue_id`. Никаких отдельных инстансов и поддоменов на заведение — заведения различаются по `slug` в пути (`/menu/:slug`).

## 2. Роли и права доступа

| Роль | Доступ |
|---|---|
| **Superadmin** | Полный доступ: список всех заведений, создание/деактивация venue, назначение админов заведениям, просмотр логов действий |
| **Venue admin** | Управление своим заведением: категории, позиции меню, фото, контакты, соцсети, часы работы, QR-код, свои сотрудники (staff) |
| **Staff** | Только переключение `is_available` у позиций своего заведения. Не может менять текст, цены, структуру |
| **Клиент** | Без аккаунта, только просмотр публичной страницы `/menu/:slug` |

Вход единый, без slug в URL (`/admin/login`), после входа — редирект в кабинет по роли и `venue_id`, привязанному к аккаунту.

## 3. Функциональные требования

### 3.1 Публичная страница меню (`/menu/:slug`)

- Список категорий → позиций: название, цена, фото (опционально), описание, теги (халяль / вегетарианское / острое / новинка)
- Переключатель языка RU/UZ (без перезагрузки состояния корзины — она тут и не нужна, состояние простое)
- Позиции с `is_available = false` показываются как "нет в наличии" (не скрываются полностью — это осознанное решение, чтобы клиент видел ассортимент целиком)
- Блок контактов внизу: соцсети (Instagram, Telegram-канал), телефон (кликабельный `tel:`), адрес со ссылкой на 2GIS, часы работы
- Кнопка "Поделиться" (Web Share API с фолбэком на копирование ссылки)
- Футер "сделано на [название сервиса]" со ссылкой на лендинг — скрывается только если у заведения включён флаг `show_powered_by = false` (платная опция)
- Быстрая загрузка на слабом интернете: минимум JS, оптимизированные изображения, кэш на сервере

### 3.2 Лендинг (главный домен `/`)

Отдельная маркетинговая страница для владельцев заведений, не для клиентов кафе:

- Оффер: что за сервис и зачем
- Как это работает — 3 шага
- Пример живого меню (ссылка на демо или реальное подключённое заведение)
- Цена / тарифы
- Форма/контакт "Подключить моё заведение"
- Ненавязчивая ссылка "Вход для заведений" → `/admin/login`

### 3.3 Админка заведения (`/admin/*`, доступ по роли)

- CRUD категорий: name_ru, name_uz, порядок сортировки (drag&drop или поле order)
- CRUD позиций: name_ru/uz, description_ru/uz, цена, теги, фото, is_available, порядок сортировки
- Управление контактами заведения: соцсети, телефон, адрес, ссылка на 2GIS, часы работы
- Генерация и скачивание QR-кода + печатного макета (table tent/наклейка)
- Настройка `show_powered_by` (если тариф позволяет)
- Управление сотрудниками (создание staff-логинов)

### 3.4 Суперадмин-панель

- Список всех заведений с статусом (активен/неактивен, до какой даты оплачено)
- Создание нового заведения (slug, название, язык по умолчанию)
- Вкл/выкл `is_active`
- Назначение/сброс пароля venue admin
- Просмотр логов действий по всем заведениям

### 3.5 QR-код и печатные материалы

- Генерация QR на `/menu/:slug` "на лету" (пакет `qrcode`)
- Экспорт PDF-макета table tent/наклейки с логотипом заведения и QR — это часть продукта, а не просто картинка QR-кода

## 4. Нефункциональные требования

- **Производительность**: страница меню должна открываться быстро на слабом 3G/wifi в заведении — это приоритет №1, от него зависит, останется ли клиент пользоваться сервисом
- **Кэширование**: публичная страница меню кэшируется (in-memory на старте, с возможностью перейти на Redis при росте), инвалидация кэша при сохранении в админке
- **Изображения**: конвертация в WebP, генерация thumbnail + полноразмерной версии при загрузке (multer + sharp), исходные тяжёлые файлы с телефона никогда не отдаются как есть
- **Безопасность**: bcrypt для паролей, rate-limiting на `/menu/:slug` и формы логина, валидация всех входных данных (joi/zod), защита от брутфорса на логине
- **Резервное копирование**: ежедневный `pg_dump` в облако с первого дня в проде, обязательный план восстановления
- **Аудит**: лог действий администраторов (кто/когда/что изменил) — таблица `admin_action_logs`
- **Неизменяемость slug**: slug заведения никогда не удаляется и не переиспользуется (QR-коды уже физически распечатаны на столах) — отключение только через `is_active = false`, при этом страница показывает "меню временно недоступно", а не 404
- **SEO и шеринг**: мета-теги и og:image для `/menu/:slug`, чтобы меню индексировалось в поиске и красиво шарилось в Telegram/Instagram
- **PWA**: manifest.json + иконка для "Добавить на экран"

## 5. Мультиязычность (RU/UZ)

- Обязательна с первого релиза, не "добавим потом"
- Все пользовательские тексты на публичной странице и в интерфейсе админки — через словари `ru.json` / `uz.json` и хелпер `t(key, lang)`
- Название/описание категорий и позиций хранятся в БД сразу в двух колонках (`_ru`, `_uz`), не в отдельной таблице переводов — это проще и достаточно для объёма данных мини-заведения
- Язык страницы меню переключается вручную клиентом, дефолт — `lang_default` заведения
- Язык интерфейса админки — по выбору администратора, хранится в сессии/cookie

## 6. Модель данных

```
venues
  id                  PK
  slug                text, unique, immutable
  name                text
  phone               text
  address             text
  address_2gis_url    text
  working_hours       jsonb            -- по дням недели
  instagram_url       text
  telegram_url        text
  lang_default        text             -- 'ru' | 'uz'
  is_active           boolean
  subscription_until  date
  show_powered_by     boolean, default true
  created_at          timestamptz

categories
  id            PK
  venue_id      FK -> venues
  name_ru       text
  name_uz       text
  sort_order    integer

items
  id                PK
  category_id       FK -> categories
  name_ru           text
  name_uz           text
  description_ru    text
  description_uz    text
  price             numeric
  currency          text, default 'UZS'
  photo_url         text
  photo_thumb_url   text
  tags              text[]            -- 'halal','vegan','vegetarian','spicy','new'
  is_available      boolean, default true
  sort_order        integer

admins
  id              PK
  venue_id        FK -> venues, nullable  -- null для superadmin
  login           text, unique
  password_hash   text
  role            text                -- 'superadmin' | 'venue_admin' | 'staff'
  created_at      timestamptz

admin_action_logs
  id            PK
  admin_id      FK -> admins
  venue_id      FK -> venues
  action_type   text        -- 'create'|'update'|'delete'|'toggle_availability'
  entity_type   text        -- 'item'|'category'|'venue'
  entity_id     integer
  details       jsonb
  created_at    timestamptz
```

Индексы: unique на `venues.slug`, индекс на `categories.venue_id`, индекс на `items.category_id`, unique на `admins.login`.

## 7. Технологический стек

- **Backend**: Node.js + Express
- **Шаблонизатор**: EJS (публичная страница и админка рендерятся на сервере — быстрее и проще, чем SPA, для этой задачи)
- **БД**: PostgreSQL (локально — Docker)
- **Миграции**: node-pg-migrate (или knex — зафиксировать на шаге 1 и не менять)
- **Сессии**: express-session + connect-pg-simple
- **Пароли**: bcrypt
- **Валидация**: zod
- **Изображения**: multer + sharp
- **QR**: пакет `qrcode`
- **PDF (table tent)**: pdf-lib или puppeteer (решить на соответствующем шаге)
- **Rate limiting**: express-rate-limit
- **i18n**: собственный лёгкий хелпер (без тяжёлых фреймворков — объём текстов небольшой)

## 9. Бизнес-правила (важно для реализации)

- Slug не удаляется и не переиспользуется никогда
- При `is_active = false` страница меню отдаёт понятное сообщение "меню временно недоступно", а не 404/500
- Первое наполнение меню заведения делает не сам владелец, а ты (через админку или xlsx-импорт) — self-service начинается после первичной настройки
- Отзывы клиентов в v1 не делаем — ссылка "Отзывы на 2GIS" вместо своей системы

## 10. Дизайн-система (UI)

Направление сознательно уходит от трёх штампов, в которые сваливается AI-дизайн по умолчанию: (1) кремовый фон + терракотовый акцент, (2) почти чёрный фон + неоновый акцент, (3) газетная вёрстка с волосяными линиями и нулевыми радиусами. Точка отсчёта — сам предмет: мини-заведение, меню как типографический объект, и локальный визуальный контекст (риштанская керамика Ферганской долины — глубокий кобальтово-бирюзовый полив, вместо дежурной терракоты).

### 10.1 Палитра

CSS-переменные, единые для всех трёх поверхностей (меню, админка, лендинг), значение переключается через `[data-theme="dark"]`:

```css
:root {
  --bg: #F4F6F5;
  --surface: #FFFFFF;
  --text-primary: #17262B;
  --text-secondary: #5C6E72;
  --accent: #1C5D6E;
  --accent-warm: #E08A3C;
  --success: #3F8F5F;
  --muted: #9AA5A3;
  --border: #DDE3E1;
  --shadow: 0 1px 2px rgba(23,38,43,.04), 0 4px 12px rgba(23,38,43,.06);
}

[data-theme="dark"] {
  --bg: #10191B;
  --surface: #17262B;
  --text-primary: #E9F1EF;
  --text-secondary: #9FB3B0;
  --accent: #4FB8C9;
  --accent-warm: #F0A855;
  --success: #6FBF8B;
  --muted: #6E807D;
  --border: #26383C;
  --shadow: none; /* в тёмной теме элевация — через border, не через тень */
}
```

`--accent-warm` используется точечно (тег "новинка", единичные акценты), не как основной цвет — иначе получится тот самый терракотовый штамп.

### 10.2 Типографика

Три роли, не одна гарнитура на всё:

| Роль | Гарнитура | Где | Вес |
|---|---|---|---|
| Display | Unbounded | заголовки лендинга, названия секций — точечно | 600–700 |
| Body | Golos Text | весь остальной текст, включая плотную админку | 400–600 |
| Utility/mono | JetBrains Mono | цены, даты, id, счётчики — табличные цифры (`font-variant-numeric: tabular-nums`) | 500 |

Перед самохостингом шрифтов — проверить покрытие кириллицы и узбекской латиницы (апостроф `oʻ`, `gʻ`) в конкретных файлах, при нехватке глифов — заменить на аналог с тем же характером.

Шкала размеров: H1 40/44 (мобильный — 32/36), H2 28/32, H3 20/26, body 16/24, body small 14/20, caption/mono-цена 15/20.

### 10.3 Сетка, отступы, радиусы, тени

- Шаг отступов (8pt grid): 4, 8, 12, 16, 24, 32, 48, 64px
- Радиусы: карточки и фото — 12px; пилюли (табы категорий, теги, кнопки-фильтры) — 999px. Форма несёт смысл: скруглённый прямоугольник = контент, пилюля = кликабельно
- Тень: мягкая, малой непрозрачности, только в светлой теме; в тёмной — элевация через `--border`, а не через тень (на тёмном фоне тени не читаются)

### 10.4 Фирменный элемент

Цена через точечный лидер — приём из классического печатного меню, не декоративный, а функциональный (мгновенно считывается взгляд "что — сколько"):

```
Плов ......................... 28 000
Шурпа ......................... 22 000
```

Название — Golos Text, цена — JetBrains Mono с `tabular-nums`, точки — тонкой линией на `--border`, не текстовыми символами. Это единственный элемент, куда вложена "смелость"; всё остальное — сдержанно.

### 10.5 Тёмная/светлая тема — техническая реализация

- Тема хранится в cookie, читается на сервере при рендере EJS, `data-theme` проставляется в `<html>` до первой отрисовки — без "мигания" неправильной темой
- Если cookie ещё нет — дефолт берётся из `prefers-color-scheme`
- JS на клике только переключает атрибут и обновляет cookie, не решает тему при загрузке страницы

### 10.6 Обязательные правила (без исключений)

- Контраст текста не ниже WCAG AA (4.5:1 обычный текст, 3:1 крупный)
- Видимый focus-state на всех интерактивных элементах (свой стиль на токенах, не `outline: none` без замены)
- Touch-target не меньше 44×44px — особенно в админке и у переключателя наличия на странице меню
- `prefers-reduced-motion` уважается: все переходы должны быть отключаемы
- Один и тот же токен-набор на всех поверхностях; отличается только плотность отступов — админка компактнее, публичное меню и лендинг просторнее
