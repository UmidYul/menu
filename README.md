# qr.menu

Сервис QR-меню для мини-заведений (кофейни, суши-студии, мини-кафе, бары).

## Дизайн-система

Визуальный стиль перенесён из референса `qr-menu-service/` (Next.js/v0-прототип, лежит в корне репозитория как справочный материал, в само приложение не подключается). Кремовый фон + терракотовый акцент, Playfair Display (заголовки) + Manrope (текст).

- `src/public/css/design-system.css` — все токены и переиспользуемые классы (`.btn`, `.card`, `.admin-shell`, `.public-menu` и т.д.).
- `src/public/css/fonts.css` + `src/public/fonts/*.woff2` — шрифты самохостятся (не с CDN). У оригинальных Fraunces/DM Sans нет кириллицы в Google Fonts — заменены на **Playfair Display** и **Manrope** (тот же характер, полная поддержка кириллицы).
- `src/views/partials/` — переиспользуемые куски вёрстки: `brand.ejs` (лого), `icon.ejs` (инлайн SVG-иконки), `admin-sidebar.ejs` / `admin-topbar.ejs` (каркас админки), `head-assets.ejs` (favicon + подключение CSS).
- Бренд-нейм сервиса — `qr.menu` (см. `src/config/constants.js`), в духе референса.

## Стек

- Node.js + Express
- EJS (серверный рендеринг)
- PostgreSQL + node-pg-migrate
- express-session + connect-pg-simple
- bcrypt, zod, multer + sharp, qrcode

## Запуск для разработки

1. Скопировать `.env.example` в `.env` и при необходимости поменять значения:

   ```
   cp .env.example .env
   ```

2. Поднять PostgreSQL через Docker:

   ```
   docker compose up -d
   ```

   Контейнер публикует Postgres на хостовом порту `5433` (а не стандартном `5432`), чтобы не конфликтовать с локально установленным PostgreSQL, если он у вас уже запущен. Это отражено в `.env.example`.

3. Установить зависимости:

   ```
   npm install
   ```

4. Прогнать миграции:

   ```
   npm run migrate:up
   ```

   Среди миграций — постоянный фикстур `/menu/demo` (заведение, категории и позиции), на который ссылается кнопка "Посмотреть демо" на лендинге. В отличие от `npm run seed` ниже, это не dev-скрипт: он выполняется в любом окружении вместе с обычными миграциями (включая продакшен), не создаёт учётных записей и ничего не печатает в консоль — так что демо-ссылка с главной страницы работает сразу после деплоя, без ручного шага.

5. (Опционально) засеять тестовые учётные записи для локальной разработки:

   ```
   npm run seed
   ```

   Скрипт идемпотентен — при повторном запуске просто пропустит уже существующие аккаунты. Создаёт вход в `/admin/login` (**только для локальной разработки**), привязывая `venue_admin` к постоянному фикстуру `demo` (см. шаг 4) — отдельное тестовое заведение больше не создаётся, demo полностью заменяет его в этой роли:

   | Логин | Пароль | Роль |
   |---|---|---|
   | `superadmin` | `superadmin123` | superadmin |
   | `venue_admin` | `venueadmin123` | venue_admin (заведение demo) |

6. Запустить сервер в режиме разработки (перезапуск при изменении файлов):

   ```
   npm run dev
   ```

7. Проверить, что сервер поднялся и подключился к БД:

   ```
   curl http://localhost:3000/health
   ```

   Должен вернуться `{"status":"ok","db":"connected"}`.

## Структура проекта

```
/src
  /routes        маршруты Express
  /controllers   обработчики маршрутов
  /models        доступ к данным (SQL-запросы)
  /middlewares   auth, роли, rate-limit и т.п.
  /views         EJS-шаблоны
  /public        статика (css/js), отдаётся по /
  /i18n          словари переводов ru.json / uz.json
  /config        конфигурация (подключение к БД и т.п.)
/migrations      миграции node-pg-migrate
/seed            скрипт наполнения БД тестовыми данными для локальной разработки
/public/uploads  загруженные пользователем фото (photo_url), разложены по /:venue_id/
```

## Загрузка фото позиций меню

- Принимаются только изображения, максимум 8 МБ на файл.
- Оригинал с телефона никогда не сохраняется как есть — конвертируется в WebP в двух размерах: превью (200px по ширине) и полноразмерная версия (800px по ширине).
- При замене или удалении фото старые файлы удаляются с диска, "мусор" не копится.
- Битый файл (не читается как изображение) не роняет сервер — возвращается понятная ошибка.

## Публичная страница меню

- `GET /menu/:slug` — отрендеренная страница кэшируется в памяти процесса (`Map` + TTL 5 минут), ключ `slug:lang`.
- Кэш инвалидируется при любом сохранении категорий/позиций этого заведения в админке — правки видны на публичной странице сразу, без ожидания истечения TTL.
- Несуществующий `slug` → честный 404. Отключённое (`is_active=false`) заведение → страница "меню временно недоступно" с HTTP 200, без падения.
- Внизу — блок контактов (телефон `tel:`, адрес со ссылкой на 2GIS, соцсети), кнопка "Поделиться" (Web Share API с фолбэком на копирование ссылки в буфер) и футер "сделано на QR-Меню", который показывается только если у заведения включён `show_powered_by` (переключает суперадмин на `/superadmin/venues` — тарифов пока нет, поэтому этим управляет только он, не сам venue_admin).
- Контакты редактируются в `/admin/venue-settings` (только venue_admin), сохранение инвалидирует кэш этого заведения.

## Мультиязычность (RU/UZ)

- Словари интерфейса: `src/i18n/ru.json`, `src/i18n/uz.json`, хелпер `t(key, lang, params)` в `src/i18n/index.js`.
- В шаблонах доступны `t(key, params)` и `lang` через `res.locals` — глобальный дефолт (`ru`) выставляет `src/middlewares/locale.js`, для `/admin/*` и `/superadmin/*` его переопределяет `src/middlewares/adminLocale.js` по cookie `admin_lang`.
- Переключатель языка админки: `GET /admin/lang?lang=ru|uz&redirect=/путь` — ставит cookie и возвращает туда, откуда пришли. Ошибки валидации форм (zod) хранят в `message` не готовый текст, а ключ словаря (например `categories.errorEmptyNameRu`), переводится в роуте через `t(...)`.
- Публичная страница меню (`/menu/:slug`): язык — `?lang=` в URL > cookie `menu_lang` (ставится автоматически при первом явном выборе, живёт сессию браузера) > `venues.lang_default`. Кэш из прошлого шага учитывает язык в ключе (`slug:lang`), так что обе языковые версии кэшируются независимо.
- Название/описание категорий и позиций уже хранятся в БД в двух колонках (`_ru`/`_uz`) — при отображении подставляется нужная, с фолбэком на другую, если конкретное поле пустое.
- В админке поля `name_ru`/`name_uz` показываются одновременно (не переключателем), чтобы администратор сразу видел непереведённые поля.

## Миграции

```
npm run migrate:up             # применить все непримененные миграции
npm run migrate:down           # откатить последнюю миграцию
npm run migrate:down -- N      # откатить последние N миграций
npm run migrate -- create some_name -j cjs   # создать новую миграцию (CommonJS-шаблон)
```

## Остановка и удаление БД

```
docker compose down          # остановить контейнер, данные сохранятся в volume
docker compose down -v       # остановить и удалить volume с данными
```
